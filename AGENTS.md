# Expo Template Guide for Coding Agents

This is an iOS-only Expo Router starter for people who may not know how to code. Make the smallest working change, run it, and explain the result and any required user action in plain language. Do not leave the user with a vague list of steps you could implement yourself.

- Onboarding lives in `src/app/onboarding/index.tsx`. The three example steps and progress bar should remain runnable while app-specific content is added.
- The main app lives in `src/app/main/`. Onboarding completion is persisted in `src/onboarding-state.tsx`; it is navigation state, not proof of an active subscription.
- Superwall is configured in `src/app/_layout.tsx` when `EXPO_PUBLIC_SUPERWALL_IOS_API_KEY` is present. The onboarding placement is `onboarding_complete`. A missing key runs the explanatory demo path.
- PostHog is configured in `src/app/_layout.tsx` and disabled until a project API key is supplied.
- Keep the default path simple: use Bun and the existing Expo, Superwall, and PostHog setup before adding another framework or service. Keep `bun.lock` in sync with dependency changes. Do not add private or organization-only dependencies.
- `ios/` is generated by Expo and ignored by Git. Never edit or commit it as the source of truth. Put native settings in `app.config.js`; prefer a dependency's Expo config plugin, or add a small, idempotent local plugin under `plugins/` and register it in `app.config.js` when needed. After native config or plugin changes, run `bun run prebuild` twice to catch duplicate or lost changes.
- Keep the iOS release path local: `scripts/release.mjs` runs Expo prebuild, Xcode archive/export, and `asc builds upload`. Do not add EAS unless the user explicitly asks to change the release path.
- Do not commit API keys, `.p8` files, `.env`, generated `ios/`, `build/`, or `node_modules/`. Ask the user for account-specific IDs or credentials when needed; never invent or hard-code them.
- Validate source changes with `bun run typecheck` and `bunx expo export --platform ios`. Test the affected flow in a simulator or device when possible, and say clearly what you could not verify.
